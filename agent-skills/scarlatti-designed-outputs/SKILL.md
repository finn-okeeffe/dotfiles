# Scarlatti designed outputs

Create practical, polished artefacts that make evidence easy to understand and act on. Use the current Scarlatti visual system consistently while retaining the user’s requested content, audience and client requirements.

## Mandatory reference

Read [references/scarlatti-design-guidelines.md](references/scarlatti-design-guidelines.md) before creating or substantially redesigning an output. It contains the active palette, typography, logo rules, document/presentation guidance, accessibility requirements and source locations.

Treat the current project brief and any client-controlled template or brand requirements as higher priority. If their conflict with the Scarlatti system materially changes the output, ask which brand should lead.

## Bundled logo assets

Use the approved logo files in [assets/logos](assets/logos) whenever a Scarlatti logo is needed. They are unmodified copies of the current lock-ups in *Scarlatti brand and colour guidelines in-house use only June 2025 V1_0 (KG)*; do not replace them with similarly named files from the SharePoint logo folder.

| Asset | Use it when |
| --- | --- |
| `scarlatti-secondary-no-tagline.png` | The audience already knows Scarlatti, including most internal work and pages with limited space. |
| `scarlatti-primary-tagline-below.png` | A cover, report, presentation or other layout needs a clear Scarlatti introduction. |
| `scarlatti-primary-tagline-right.png` | A wide, shallow header needs the primary mark while preserving vertical space. |

All three lock-ups have a white background. Place them on white, retain their aspect ratio and clear space, and use the source file unchanged. Do not reverse, recolour, crop, trace or recreate a logo. No current inverted or all-white lock-up is bundled: put the standard mark on a white panel for a dark or partner-colour background rather than using an older logo.

## Workflow

1. Identify the output type, audience, purpose, delivery medium and whether it is internal, external or co-branded.
2. Locate the closest current Scarlatti template or supplied asset. Start from it rather than recreating the layout. Preserve masters, named styles, margins and existing structure.
3. Read the design reference and apply its active palette, typography and visual hierarchy. Select and use the matching bundled logo asset; do not redraw it or copy it from a screenshot.
4. Make the central message immediately clear. Use a strong heading, concise explanation and only the evidence, visual or call to action required to support it.
5. Apply the format-specific rules in the reference for reports, slides, charts, tables, icons, diagrams, imagery or digital concepts.
6. Check the output against the quality gate below before handing it off.

## Design decisions

- Make the work clear, human, analytical, quietly confident and action-oriented.
- Use orange as a controlled Scarlatti accent. Do not make every element orange; let primary colours and whitespace do most of the structural work.
- Keep typography, case, spacing, alignment, icon family and visual treatment consistent.
- Prefer authentic people-and-work imagery, straightforward diagrams and direct data labels over decorative effects or generic corporate stock imagery.
- For charts and tables, answer the reader’s question first. Reformat any Office-default chart fully or use the supplied chart template.
- Build in accessibility: adequate text contrast, readable minimum sizes, direct labels and non-colour cues for meaningful distinctions.

## Quality gate

Confirm all of the following:

- The main message is understandable within five seconds.
- The correct logo variant, active colours and approved fonts are used.
- The layout feels spacious and follows the relevant template; no default Office styling remains.
- Text is readable and contrast is appropriate for its size and background.
- Data is accurate, clearly labelled and not misleading.
- Photos, icons and co-branding are relevant, consistently treated and permitted for use.
- The result is useful to its intended reader and ends with a clear next step where appropriate.

## Delivery notes

Briefly state which template or visual system was applied, what was created or changed, and any unresolved client-brand, accessibility, asset-licensing or source-data decisions. Do not modify source templates or SharePoint material unless the user explicitly asks and has placed that location in scope.
